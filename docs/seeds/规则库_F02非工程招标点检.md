# F02 非工程招标采购文件点检规则库

规则库版本 V1.0。适用表单：F02 非工程招标采购文件呈批表。规则来源：集团《非工程类采购规则》（协审流程 = 非工程招标采购文件呈批表）。
本库共 8 条审核要素规则，供 F02 采购文件点检使用。每条结论的级别只取「风险 / 关注 / 通过」三值，规则原文中的「否决」一律记为「风险」。

## 附件角色与识别方法

规则中的数据锚点用 A00–A04 表示逻辑角色，不是固定文件名。实际上传的附件名称不固定，必须先读内容、再结合文件名判定每份材料属于哪个角色，再按角色核验。不得因为文件名不含「呈批表」「合同」等字样就判定该材料缺失。

A00 = OA 呈批表（非工程招标采购文件呈批表）。识别特征：内容为表单/JSON，含 form_fields（采购方式、预算金额、最高限价、投标保证金）与 attachments 清单；文件名常含呈批、OA、审批、F02。
A01 = 采购方案文件。识别特征：内容含项目概况、采购需求清单、采购方式建议、采购范围或技术需求；文件名常含方案、需求、立项。
A02 = 采购决策纪要。识别特征：内容为会议纪要体，含会议时间、参会人员、决议事项、表决意见，并载明采购方式；文件名常含纪要、会议、决策、专题。
A03 = 采购（招标）文件全文。识别特征：内容含招标公告或投标邀请、投标人须知、资格条件、评分细则、合同条款等章节；文件名常含招标、采购文件、谈判文件、询价文件。
A04 = 合同模板。识别特征：内容为合同条款体，含甲方乙方、标的、付款、验收、履约保证金、违约责任等条款，且通常是 A03 的附件；文件名常含合同、协议、模板。

识别流程：第一步列出当前任务沙箱中的全部附件并逐个读取；第二步按上述内容特征判定角色，文件名只作辅助线索，内容与文件名冲突时以内容为准；第三步把「文件名 → 角色」映射写入字段 attachment_role_map，把各角色正文写入 source_docs；第四步核对 A00–A04 是否齐全，缺失的角色在 R01 记录，不得凭文件名猜测其正文。一份附件只能归属一个角色；若一份文件同时含多个角色的内容（如招标文件内附合同模板），按主内容归 A03，并在角色映射中备注其内含 A04 内容。

## 总则：级别与综合结论口径

每条 item 的 level 取该条规则「级别映射」的对应值，只能是 风险 / 关注 / 通过，不得用预警、不通过、异常等词。
综合结论 conclusion 的归纳口径：全部通过 → 建议通过；存在风险且可补正 → 建议有条件通过（condition 必填）；存在风险且不可补正 → 建议不通过；仅有关注 → 建议通过，关注事项跟进。
摘要 summary 固定句式：共评审 8 项：X 项风险、Y 项关注、Z 项通过；一句话处理意见。X+Y+Z 必须等于 8，且必须与 items 实际级别统计一致。
有风险项时 conclusion 不得为「建议通过」。

## ZC-F02-R01 流程附件资料齐全

审核要素：流程附件资料齐全。又称必备附件、附件齐备性。
判定规则：按必备附件清单逐项点验——采购方案文件（A01）、决策纪要文件包（A02）、采购（招标）文件全文（A03）。
级别映射：决策纪要缺失 → 关注（提示补正，不阻断）；采购方案文件或采购（招标）文件全文缺失 → 风险（否决）；三项齐备 → 通过。
数据锚点：A00 的 attachments[] 各附件 type 与是否存在；A01 / A02 / A03 是否有正文。
检索关键词：附件齐全、必备附件、附件缺失、漏附、采购方案没交、决策纪要没交、招标文件没交、齐备性点验、否决。

## ZC-F02-R02 采购方式合规

审核要素：采购方式合规。又称采购方式一致性。
判定规则：比对 A02 决策纪要载明的采购方式与 A00 呈批表 form_fields.采购方式是否一致；同时校验最高限价不高于预算金额。
级别映射：采购方式不一致，或最高限价高于预算金额 → 风险（否决）；两者一致且限价合规 → 通过。
数据锚点：A00 的 form_fields.采购方式、预算金额、最高限价；A02 决议事项一。
检索关键词：采购方式、公开招标、竞争性磋商、询价、谈判、与决策纪要不一致、擅自变更采购方式、最高限价超预算、限价高于预算、否决。

## ZC-F02-R03 招标文件文本检查

审核要素：招标文件文本检查。又称采购文件文本一致性。
判定规则：对采购（招标）文件全文做上下文一致性、错漏、敏感信息、格式规范检查；重点核对同一数值在第二章前附表、第五章评分细则、第六章合同条款之间是否自洽。
级别映射：发现上下文矛盾、错漏、敏感信息或格式规范问题任一 → 关注；无 → 通过。
数据锚点：A03 全文，尤其第二章前附表、第五章评分细则、第六章合同条款的金额与限价。
检索关键词：招标文件前后不一致、限价写错、金额矛盾、上下文不一致、错漏、敏感信息、格式规范、文本检查。

## ZC-F02-R04 资格要求

审核要素：资格要求。又称资格条件关联性。
判定规则：逐条比对资格条件与采购需求的关联性。出现以下任一即命中：特定品牌或专利或产地；指定特定客户或项目业绩；资质等级超出项目规模；地域性限制条件。
级别映射：命中任一 → 风险（否决）；资格条件均与采购需求相关且无上述限制 → 通过。
数据锚点：A03 第三章资格条件（3.1 至 3.6）；A01 采购需求清单。
检索关键词：资格条件、地域限制、本地业绩、珠海业绩、指定品牌、原厂授权书、专利、产地、指定客户、特定项目业绩、资质等级过高、排斥潜在投标人、否决。

## ZC-F02-R05 投标保证金

审核要素：投标保证金。又称保证金合规。
判定规则：比对招标文件保证金项——金额不得超过项目上限价的 2%；未设置保证金或超过上限即异常；递交方式不得排除保函、保险保单等合法替代形式。
级别映射：无保证金、超过上限价 2%、或只接受现金不接受保函保险任一 → 关注；金额合规且接受保函或保险 → 通过。
数据锚点：A00 的 form_fields.投标保证金金额、保证金递交方式、最高限价；A03 第四章投标保证金。
检索关键词：投标保证金、保证金比例、上限价 2%、保证金超限、只收现金、不接受保函、保险保单、担保公司保函、递交方式、现金转账。

## ZC-F02-R06 商务及合同核心条款

审核要素：商务及合同核心条款。又称合同核心条款。
判定规则：核对四类问题——（1）履约保证金超过合同金额 10%，或只收现金不接受保函保险，或退还节点与条件不清、设不合理前置条件；（2）付款节点、比例、验收条件不合理、单方面转嫁风险，或无合理依据设超长质保与回款周期；（3）验收标准模糊无量化指标、验收主体或流程缺失、设与项目无关的验收否决项；（4）违约条款权责不对等、仅约束供应商免除甲方责任，或违约金上限不合理。
级别映射：命中上述任一 → 关注；四类均合规 → 通过。
数据锚点：A04 第 5、6、7、9、12 条；A00 的履约保证金比例、合同金额。
检索关键词：履约保证金、超过 10%、现金、不接受保函、保证金退还、付款比例、验收标准、量化验收指标、验收主体、质保期、违约金上限、甲方免责、权责不对等、单方面转嫁风险。

## ZC-F02-R07 评分细则

审核要素：评分细则。又称评分标准。
判定规则：核对评分细则是否出现——特定单一品牌名或专利或特定产地；业绩要求指定特定客户或项目、或超出项目规模；技术参数高于行业通用标准；地域性限制条件。
级别映射：命中任一 → 关注；无 → 通过。
数据锚点：A03 第五章评分细则（5.1 至 5.5）。
检索关键词：评分细则、评分标准、品牌加分、指定品牌、单一品牌、专利、产地、技术参数、高于行业通用标准、检测报告、地域限制、本地业绩加分、业绩指定客户。

## ZC-F02-R08 异议澄清弃标流程约定

审核要素：异议澄清弃标流程约定。又称异议澄清与弃标处理。
判定规则：核对三类流程是否完备——（1）异议或质疑的受理主体、时限、答复要求是否完备，是否限制供应商正常异议权利；（2）澄清补遗是否写明「实质性变更需重新公告并顺延投标截止时间」；（3）中标候选人弃标后重新招标还是顺延，处理流程是否明确。
级别映射：三类任一缺失或不明确 → 关注；三类均完备 → 通过。
数据锚点：A03 第七章异议与澄清（7.1 至 7.5）。
检索关键词：异议、质疑、受理主体、答复时限、限制异议权利、澄清补遗、实质性变更、重新公告、顺延投标截止时间、弃标、中标候选人放弃、重新招标、顺延。
