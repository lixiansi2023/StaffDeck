# ZC-F02-R03 招标文件文本检查

> 规则库 V1.0 ｜ 适用表单：F02 非工程招标采购文件呈批表 ｜ 规则来源：集团《非工程类采购规则》（协审流程）
> 条目 03 / 08 ｜ 对应 SOP 节点：`n3_text` ｜ 结论槽位：`review_03`

## 1. 审核要素

对采购（招标）文件全文做文本质量检查，发现上下文矛盾、错漏、敏感信息或格式规范问题。又称「采购文件文本一致性」。

## 2. 通用判定口径

- 结论级别仅可为 **风险 / 关注 / 通过** 三值；规则原文中的「否决」统一记为「风险」，不得使用「预警」「不通过」「异常」等词。
- 附件角色按**内容**识别，文件名只作辅助线索。
- 8 项汇总口径：全部通过 → 建议通过；有风险且可补正 → 建议有条件通过（`condition` 必填）；有风险且不可补正 → 建议不通过；仅有关注 → 建议通过，关注事项跟进。**存在风险项时，综合结论不得为「建议通过」。**
- 本规则为 8 项中的第 03 项，`rule_id = ZC-F02-R03`；本规则只产生 **关注 / 通过**，不产生「风险」。

## 3. 本规则涉及的附件角色

| 角色 | 名称 | 内容识别要点 |
| --- | --- | --- |
| A03 | 采购（招标）文件全文 | 含招标公告 / 投标邀请、投标人须知、资格条件、评分细则、合同条款等章节 |

## 4. 判定步骤

1. 从 `source_docs` 取 A03 对应的 `workspace_path`，读取招标文件正文（n0 只存路径，未存正文）。
2. 按四个维度逐项检查：
   - **上下文一致性**：同一数值（尤其最高限价、金额）在第二章前附表、第五章评分细则、第六章合同条款之间是否自洽；
   - **错漏**：章节缺失、条款编号断档、关键字段空缺；
   - **敏感信息**：不应公开的个人信息、内部意见或其他投标人信息；
   - **格式规范**：表述歧义、编号混乱、排版残缺。
3. 重点核对第二章前附表的限价值与第五章、第六章中所述限价是否一致。
4. `opinion` 必须写明具体章节与数值；`evidence` 写明 A03 的相关章节号。

## 5. 级别映射

| 情形 | level |
| --- | --- |
| 发现上下文矛盾、错漏、敏感信息、格式规范问题中的任意一项 | 关注 |
| 四类问题均未发现 | 通过 |

## 6. 数据锚点

- `A03` 全文，尤其：
  - 第二章 前附表（最高限价）
  - 第五章 评分细则（限价表述）
  - 第六章 合同条款（金额 / 限价）

## 7. 检索关键词

招标文件前后不一致、限价写错、金额矛盾、上下文不一致、错漏、敏感信息、格式规范、文本检查
