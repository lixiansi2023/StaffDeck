# ZC-F02-R02 采购方式合规

> 规则库 V1.0 ｜ 适用表单：F02 非工程招标采购文件呈批表 ｜ 规则来源：集团《非工程类采购规则》（协审流程）
> 条目 02 / 08 ｜ 对应 SOP 节点：`n2_method` ｜ 结论槽位：`review_02`

## 1. 审核要素

核对呈批表申报的采购方式与决策纪要是否一致，并校验最高限价不突破预算金额。又称「采购方式一致性」。

## 2. 通用判定口径

- 结论级别仅可为 **风险 / 关注 / 通过** 三值；规则原文中的「否决」统一记为「风险」，不得使用「预警」「不通过」「异常」等词。
- 附件角色按**内容**识别，文件名只作辅助线索；不得因文件名不含「呈批表」「纪要」等字样就判定缺失。
- 8 项汇总口径：全部通过 → 建议通过；有风险且可补正 → 建议有条件通过（`condition` 必填）；有风险且不可补正 → 建议不通过；仅有关注 → 建议通过，关注事项跟进。**存在风险项时，综合结论不得为「建议通过」。**
- 本规则为 8 项中的第 02 项，`rule_id = ZC-F02-R02`；本规则只产生 **风险 / 通过**，不产生「关注」。

## 3. 本规则涉及的附件角色

| 角色 | 名称 | 内容识别要点 |
| --- | --- | --- |
| A00 | OA 呈批表 | 表单 / JSON，`form_fields` 含 `采购方式`、`预算金额`、`最高限价` |
| A02 | 采购决策纪要 | 会议纪要体，含决议事项、表决意见，并在「决议事项一」载明采购方式 |

## 4. 判定步骤

1. 从 `source_docs` 取 A00、A02 对应的 `workspace_path`，读取两份文件正文（n0 只存路径，未存正文）。
2. **比对采购方式**：将 `A00.form_fields.采购方式` 与 `A02.决议事项一` 载明的采购方式逐字比对，不一致即命中风险。
3. **校验限价**：计算 `最高限价 ≤ 预算金额`；若最高限价高于预算金额，即命中风险。
4. `opinion` 必须写出两处采购方式的原值，以及预算金额、最高限价的具体数值；`evidence` 写明比对来源。

## 5. 级别映射

| 情形 | level |
| --- | --- |
| 采购方式不一致（否决） | 风险 |
| 最高限价高于预算金额（否决） | 风险 |
| 采购方式一致，且最高限价不高于预算金额 | 通过 |

> 两项同时异常仍只出一条结论，`level` 取「风险」，并在 `opinion` 中并列说明所有异常点。

## 6. 数据锚点

- `A00.form_fields.采购方式`
- `A00.form_fields.预算金额`
- `A00.form_fields.最高限价`
- `A02.决议事项一`（载明的采购方式）

## 7. 检索关键词
