# ZJ-R02 收、支单位名称

> 规则库 V1.0 ｜ 适用流程：融资资金类-资金下拨 ｜ 规则来源：`input/资金/资金审阅规则.xlsx`（集团资金类协审流程规则表）
> 条目 02 / 08 ｜ 本流程内第 02 / 03 项 ｜ 结论槽位：`review_02`

## 1. 审核要素

核对付款方、收款方单位名称是否与主数据全称一致，防止错付。又称「收支单位名称一致性」。

## 2. 通用判定口径

- 结论级别仅可为 **风险 / 关注 / 通过** 三值；规则原文中的「否决」「拦截」统一记为「风险」，「预警」统一记为「关注」，不得使用「不通过」「异常」等词。
- 数据来源按**内容**识别，文件名只作辅助线索。
- 综合结论口径：全部通过 → 建议通过；有风险且可补正 → 建议有条件通过（`condition` 必填）；有风险且不可补正 → 建议不通过；仅有关注 → 建议通过，关注事项跟进。**存在风险项时，综合结论不得为「建议通过」。**
- 本规则 `rule_id = ZJ-R02`；只产生 **关注 / 通过**，不产生「风险」。

## 3. 本规则涉及的数据来源角色

| 角色 | 名称 | 内容识别要点 |
| --- | --- | --- |
| B00 | 待审表单（费控系统） | 资金下拨表单，含付款方名称、收款方名称 |
| B02 | 账户台账 / 银企主数据 | 单位全称、简称、曾用名、合并范围 / 白名单 |

> 校验须区分付款方与收款方两个方向，不得只核其中一个。

## 4. 判定步骤

1. 从 `source_docs` 取 B00、B02 对应路径，读取两份材料正文。
2. 将 B00 付款方名称、收款方名称分别与 B02 全称**逐字比对**，覆盖简称、曾用名、错字三类偏差。
3. 核对收款方是否在合并范围 / 白名单内；非合并范围 / 白名单收款方 → 关注，须附审批依据。
4. 名称不符（简称/曾用名/错字未澄清）或收款方非白名单且无审批依据 → 关注；两个方向全称一致且在合并范围/白名单 → 通过。
5. `opinion` 必须写出两个方向的名称原值、比对结果与是否白名单；`evidence` 写明 B02 对应条目。

## 5. 级别映射

| 情形 | level |
| --- | --- |
| 名称不符（简称/曾用名/错字未澄清） | 关注 |
| 收款方非合并范围/白名单，且未附审批依据 | 关注 |
| 付款方、收款方全称均一致，且收款方在合并范围/白名单内 | 通过 |

## 6. 数据锚点

- `B00.付款方名称`
- `B00.收款方名称`
- `B02.单位全称 / 简称 / 曾用名 / 合并范围 / 白名单`

## 7. 检索关键词

收支单位名称、付款方、收款方、全称逐字比对、简称、曾用名、错字、银企主数据、合并范围、白名单、审批依据
