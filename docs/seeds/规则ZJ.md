一次评审只覆盖当次协审流程所适用的规则，**不是 8 项全评**。规则未触发时不产生判定项，不得以「通过」代替「不执行」。综合结论的 X + Y + Z 等于实际执行项数。

## 数据来源与识别方法

规则中的数据锚点用 B00–B04 表示逻辑来源，不是固定文件名。实际材料名称不固定，必须先读内容再判定归属，不得因文件名不含「余额表」「纪要」「台账」等字样就判定缺失。

B00 = 待审表单（费控系统）。识别特征：费用/资金下拨、借款申请、出借审批、还本付息申请表，含下拨金额、收/支单位名称与账号、融资主体/金额/期限/利率/金融机构等字段。
B01 = 资金池归集余额表。识别特征：资金系统 T-1 日终快照，含「可用余额」（已剔除受限/冻结/质押）与快照日期。
B02 = 账户台账 / 银企主数据。识别特征：单位全称（含简称、曾用名）、账号、户名↔账号映射、备案清单、合并范围 / 白名单。
B03 = 董事会（三会）决议 / 会议纪要。识别特征：决议类型、日期、文号、议题、审议金额、表决结果、签章。
B04 = 贷款信息汇总表（BIP 资金系统）。识别特征：借款人、贷款余额、贷款人、还本付息节点。

识别流程：先列出本次任务全部材料并逐个读取；按上述内容特征判定来源角色，文件名只作辅助线索；在 SOP 的 source_docs 槽位只保存来源角色到材料路径的映射，正文按需读取，不写入槽位；再按当次流程核对所需来源是否齐全。同一份材料含多个来源内容时按主来源归属并备注。除 R01 明确规定快照缺失「待补正转人工」、R04/R06 明确规定决议缺失「关注」外，其他材料缺失的级别是**执行兜底建议**：标为「关注（待补正）」且说明无法完成实质判定，不把缺失视为通过或风险命中；该兜底不是 Excel 原文。

## 总则：级别与综合结论口径

每条已执行 item 的 level 取该条规则「级别映射」的对应值，只能是 风险 / 关注 / 通过。原表 D 列明确写「风险·拦截」或「任一不符→风险」时，按风险执行，H 列原文作为口径依据保留。阈值、三会口径及决议有效期未给定时不得自行编造。

综合结论 conclusion 的归纳口径：全部通过 → 建议通过；存在风险且可补正 → 建议有条件通过（condition 必填）；存在风险且不可补正 → 建议不通过；仅有关注 → 建议通过，关注事项跟进。有风险项时 conclusion 不得为「建议通过」。

摘要 summary 固定句式：共评审 N 项：X 项风险、Y 项关注、Z 项通过；一句话处理意见。N 为当次实际执行项数，X+Y+Z 必须等于 N，且必须与 items 实际级别统计一致。还本付息流程 R08 未触发时须单独说明「本次规则不执行」，不得生成虚假的通过项或普通协审结论。

## ZJ-R01 资金池归集余额

审核要素：核对下拨金额是否超出资金池可用余额，防止超余额下拨、挤占最低备付。又称「归集余额充足性」。
判定规则：读 B01 T-1 日终快照「可用余额」（剔除受限/冻结/质押）与快照日期，比对 B00 下拨金额；可用余额 < 下拨金额＋最低备付额 → 风险·拦截；差额偏小 → 关注·资金部复核；快照过期或缺失 → 关注·待补正转人工。
级别映射：在最低备付额已经确定时，可用余额不足 → 风险；差额落入资金部确定的关注区间、快照过期/缺失 → 关注；余额充足、差额不在关注区间且快照有效 → 通过。最低备付额、关注区间、快照有效天数在原表均为空白占位，未给定时只记录「关注（待补正）」并要求资金部提供，不推断风险或通过。
数据锚点：B00.下拨金额；B01.可用余额 / 快照日期（阈值最低备付额、差额、快照有效天数待资金部给定）。
口径依据：D2 写余额不足「风险·拦截」，H2 写「关注」，本库按 D2 记风险，H2 原文作为口径依据保留。
检索关键词：资金池归集余额、归集余额不足、可用余额、最低备付额、受限冻结质押、T-1 日终、快照过期、风险拦截、资金部复核、待补正转人工。

## ZJ-R02 收、支单位名称

审核要素：核对付款方、收款方单位名称是否与主数据全称一致，防止错付。又称「收支单位名称一致性」。
判定规则：与 B02《集团账户台账/银企主数据》全称逐字比对（含简称、曾用名、错字），区分付款方与收款方两个方向；收款方非合并范围 / 白名单 → 关注，须附审批依据。
级别映射：名称不符（简称/曾用名/错字未澄清）或收款方非白名单且无审批依据 → 关注；两方向全称一致且在合并范围/白名单 → 通过。
数据锚点：B00.收款方名称 / 付款方名称；B02.单位全称 / 简称 / 曾用名 / 合并范围 / 白名单。
检索关键词：收支单位名称、付款方、收款方、全称逐字比对、简称、曾用名、错字、银企主数据、合并范围、白名单、审批依据。

## ZJ-R03 收支单位账号

审核要素：核对收/支账号是否为备案账户、户名与账号是否成对一致。又称「账号一致性」。
判定规则：账号逐位一致 + 户名↔账号成对校验（两条要素共用一条校验逻辑）+ 账户在备案清单内；非备案账户、变更无证明 → 风险·拦截。
级别映射：账号非逐位一致、户名账号不成对、非备案账户或变更无证明 → 风险；三项均符合 → 通过。
数据锚点：B00.收款方账号 / 付款方账号 / 户名；B02.账号备案清单 / 户名↔账号映射 / 账户变更证明。
检索关键词：收支单位账号、账号逐位一致、户名账号成对、备案账户、变更无证明、风险拦截、账号错误。
口径依据：原表 H 列记为「关注」，D 列判定说明为「风险·拦截」，本库按 D 列否决级记「风险」，H 列原文作为口径依据保留。

## ZJ-R04 融资事项经过集团三会审议

审核要素：核对融资事项是否经集团「三会」审议、决议是否有效。又称「融资决策程序」。
判定规则：先定义「三会」口径（党委会/经营班子会/董事会）；核对 B03 决议类型、日期、文号、议题、审议金额、表决结果、签章七项；缺决议 → 关注（建议补正）；决议晚于申请、事项不符 → 风险·拦截。D5 记风险·拦截、H5 记关注，本库按 D5 记风险，H5 原文作为口径依据保留。
级别映射：缺决议 → 关注；决议晚于申请 / 事项不符 → 风险；决议齐全且有效 → 通过。原表要求核对签章，却未单独定义「签章缺失」的影响；发现缺失时记录关注（待补正）并说明原表未定义该级别，不能声称原表规定为风险。
数据锚点：B03.决议七项核对信息；B00.融资借款申请表申请日期 / 审议金额 / 融资事项。依据《珠海交通控股集团有限公司融资管理制度（试行）》。
检索关键词：融资事项、三会审议、党委会、经营班子会、董事会、决议、文号、表决结果、签章、缺决议、决议晚于申请、事项不符、风险拦截。

## ZJ-R05 融资主体、金额、期限、利率、金融机构符合决议

审核要素：核对融资申请五要素是否落入决议批复范围。又称「融资要素与决议一致」。
判定规则：按 5 个字段逐项拆开比对——主体（可能为简称）、金额（大小写一致，金额 ≤ 决议金额）、期限（≤ 决议期限）、利率（≤ 批复上限）、金融机构（可能为简称）；任一不符 → 风险。
级别映射：五要素任一超出决议/批复或大小写不一致 → 风险；五项均符合 → 通过。
数据锚点：B00.融资主体 / 金额 / 期限 / 利率 / 金融机构；B03.决议对应五项批复。依据《珠海交通控股集团有限公司融资管理制度（试行）》。
检索关键词：融资主体、融资金额、融资期限、利率、金融机构、决议过期、大小写一致、超决议金额、超批复上限、简称、任一不符、风险。

## ZJ-R06 出借决策程序

审核要素：核对资金出借事项是否经集团「三会」审议、决议是否有效。又称「出借决策程序」。
判定规则：先定义「三会」口径（党委会/经营班子会/董事会）；核对 B03 决议类型、日期、文号、议题、审议金额、表决结果、签章七项；缺决议 → 关注（建议补正）；决议晚于申请、事项不符 → 风险·拦截。D7 记风险·拦截、H7 记关注，本库按 D7 记风险，H7 原文作为口径依据保留。
级别映射：缺决议 → 关注；决议晚于申请 / 事项不符 → 风险；决议齐全且有效 → 通过。原表要求核对签章，却未单独定义「签章缺失」的影响；发现缺失时记录关注（待补正）并说明原表未定义该级别，不能声称原表规定为风险。
数据锚点：B03.决议七项核对信息；B00.资金出借审批单申请日期 / 出借金额 / 借款人。依据《珠海交通控股集团有限公司内部借款管理制度（2026年修订）》。
检索关键词：资金出借、出借决策、三会审议、党委会、经营班子会、董事会、决议、文号、表决结果、签章、缺决议、决议晚于申请、风险拦截。

## ZJ-R07 资金出借主体、借款人主体、金额、期限符合决议

审核要素：核对出借审批四要素是否落入决议批复范围。又称「出借要素与决议一致」。
判定规则：按 4 个字段逐项拆开比对——出借主体、借款人主体（可能为简称）、金额（大小写一致，金额 ≤ 决议金额）、期限（≤ 决议期限）；任一不符 → 风险。
级别映射：四要素任一超出决议或大小写不一致 → 风险；四项均符合 → 通过。
数据锚点：B00 表单取对应字段（出借主体 / 借款人主体 / 金额 / 期限）；B03.决议对应四项批复。依据《珠海交通控股集团有限公司内部借款管理制度（2026年修订）》。
检索关键词：出借主体、借款人主体、出借金额、出借期限、决议过期、大小写一致、超决议金额、简称、任一不符、风险。

## ZJ-R08 还本付息金额、时间、金融机构与 BIP 匹配

审核要素：核对还本付息申请与 BIP 资金系统贷款信息是否一致。又称「还本付息与 BIP 匹配」。
判定规则：仅当贷款人为外部金融机构时执行本规则，否则不执行。从 B04《贷款信息汇总表》取借款人（可能为简称）、贷款余额（≥ 还本金额）、贷款人（可能为简称），与 B00 还本付息申请表的金额、时间、金融机构比对；要素漏填 / 有误或不符 → 风险。
级别映射：仅贷款人为外部金融机构时，金额 / 时间 / 金融机构任一不符、贷款余额不足还本金额、要素漏填有误 → 风险；均匹配且无漏填 → 通过。贷款人为非外部金融机构 → 原表明确写「否则不执行」，不生成通过项。贷款人性质无法核实时，先核实适用条件，不擅自判风险或通过。
数据锚点：B00 表单取对应字段（还本付息金额 / 时间 / 金融机构）；B04.借款人 / 贷款余额 / 贷款人。依据《珠海交通控股集团有限公司融资管理制度（试行）》。
检索关键词：还本付息、BIP、贷款信息汇总表、贷款余额、还本金额、借款人、贷款人、金融机构、外部金融机构、要素漏填、不匹配、风险。
