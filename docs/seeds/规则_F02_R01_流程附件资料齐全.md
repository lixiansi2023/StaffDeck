# ZC-F02-R01 流程附件资料齐全

> 规则库 V1.0 ｜ 适用表单：F02 非工程招标采购文件呈批表 ｜ 规则来源：集团《非工程类采购规则》（协审流程）
> 条目 01 / 08 ｜ 对应 SOP 节点：`n1_attachment` ｜ 结论槽位：`review_01`

## 1. 审核要素

核对本次呈批是否随附全部必备材料，防止缺件审查。又称「必备附件」「附件齐备性」。

## 2. 通用判定口径

- 结论级别仅可为 **风险 / 关注 / 通过** 三值；规则原文中的「否决」统一记为「风险」，不得使用「预警」「不通过」「异常」等词。
- 附件角色按**内容**识别，文件名只作辅助线索；不得因文件名不含「呈批表」「合同」等字样就判定该材料缺失。
- 8 项汇总口径：全部通过 → 建议通过；有风险且可补正 → 建议有条件通过（`condition` 必填）；有风险且不可补正 → 建议不通过；仅有关注 → 建议通过，关注事项跟进。**存在风险项时，综合结论不得为「建议通过」。**
- 本规则为 8 项中的第 01 项，`rule_id = ZC-F02-R01`。

## 3. 本规则涉及的附件角色

| 角色 | 名称 | 内容识别要点 |
| --- | --- | --- |
| A00 | OA 呈批表 | 表单 / JSON，含 `form_fields`（采购方式、预算金额、最高限价、投标保证金）与 `attachments` 清单 |
| A01 | 采购方案文件 | 项目概况、采购需求清单、采购方式建议、采购范围或技术需求 |
| A02 | 采购决策纪要 | 会议纪要体，含会议时间、参会人员、决议事项、表决意见，并载明采购方式 |
| A03 | 采购（招标）文件全文 | 招标公告 / 投标邀请、投标人须知、资格条件、评分细则、合同条款等章节 |

> 一份附件只归一个主角色；若同一文件含多个角色内容（如招标文件内附合同模板），按主内容归 A03，并在 `attachment_role_map` 备注内含 A04 内容。

## 4. 判定步骤

1. 读取槽位 `attachment_role_map` 的「文件名 → 角色」映射；本规则只需角色映射，不读正文。
2. 逐项点验必备附件是否有正文：A01 采购方案文件、A02 决策纪要文件包、A03 采购（招标）文件全文。
3. 按第 5 节给出 `level`；`opinion` 需点明缺失角色对应的实际文件名，或写明三项齐备。

## 5. 级别映射

| 情形 | level |
| --- | --- |
| A02 决策纪要缺失（提示补正，不阻断） | 关注 |
| A01 采购方案文件缺失（否决） | 风险 |
| A03 采购（招标）文件全文缺失（否决） | 风险 |
| A01 / A02 / A03 三项齐备 | 通过 |

> 多项同时缺失时取最高级别（风险）。

## 6. 数据锚点

- `A00.attachments[]`：各附件 `type` 与是否存在。
- `A01` / `A02` / `A03`：是否有正文。

## 7. 检索关键词

附件齐全、必备附件、附件缺失、漏附、采购方案没交、决策纪要没交、招标文件没交、齐备性点验、否决
